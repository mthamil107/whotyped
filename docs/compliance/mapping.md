# Compliance mapping

How whotyped output supports common controls. This is a mapping, not a certification. Auditors decide what satisfies a control; this table tells you which whotyped artefact to hand them.

Artefacts referenced below:

- `alerts.jsonl` (default `/var/lib/whotyped/alerts.jsonl`), one JSON object per line, schema `whotyped.alert.v1`. Fields: `ts`, `host`, `event`, `class`, `mode`, `user`, `src_ip`, `key_fingerprint`, `agent`, `score`, `level`, `reasons[]` (`clue`, `category`, `weight`, `evidence`), `suppressed[]`, `session_id`, `connections`, `window`, `freeze_window`, `actions_hint`.
- Weekly report: `whotyped report --since 7d --by account|server|agent|key --format md`.
- `whotyped check --json`: which readers are active and what coverage the host has (sshd log level, auditd rule present, procfs access).

## What this is not

whotyped produces evidence, not proof. Scores are probabilistic: a `suspected_agent` at 82 means several independent clues agreed, not that an agent was present. Agents that mimic humans or stay quiet can evade it, and it sees only what sshd, auditd and `/proc` expose on that host. It does not enforce anything, does not block sessions, does not record keystrokes or command text by default, and does not replace access management, session recording or an EDR. Do not present it to an auditor as a control by itself; present it as a detective source feeding an existing monitoring control.
