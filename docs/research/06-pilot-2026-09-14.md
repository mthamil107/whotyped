# Pilot on a real server (2026-09-14)

A single-host pilot. whotyped ran monitor-only on a real, shared Ubuntu server for about 25 minutes. Real AI agents operated the host over SSH. The host was then restored to its prior state. This is the first test on real agent traffic rather than scripted or hand-built sessions.

## Setup

| Item | Value |
|---|---|
| Host | Ubuntu 20.04.3 LTS, kernel 5.4, 8 CPUs, running a K3s cluster and databases |
| OpenSSH | 8.2p1, older than any version in the fixtures |
| Install path | the documented one: `whotyped check --fix`, `sshd -t`, `systemctl reload ssh`, `augenrules --load`, systemd unit |
| Readers | journald (sshd), auditd 2.8.5 (installed for the pilot), /proc |
| sshd | `LogLevel VERBOSE`, `AcceptEnv AI_AGENT`, the sshrc declaration hook; no DEBUG1, so no banner clue |
| Test accounts | three throwaway accounts, one per scenario, removed afterwards |
| Clients | ran from a workstation over the internet |

## Sessions

| Session | Client | Commands |
|---|---|---|
| Claude Code, undeclared, run 1 | a Claude Code agent using its shell tool, one OpenSSH connection per command, health review | 16 |
| Claude Code, declared | same, with `-o SetEnv=AI_AGENT=claude-code`, log and time review | 12 |
| paramiko client | paramiko 4.0, one transport, 14 exec channels, 1.5 to 4 s apart, no PTY | 14 |
| Claude Code, undeclared, run 2 | a new agent with a different task (security snapshot), after the fixes | 15 |
| paramiko client, run 2 | same client, after the fixes | 14 |

Every command was read-only. No human test sessions were run. The host's own traffic during the window was internet password guessing and an administrator's automation.

## What whotyped reported

| Session | Before fixes | After fixes (live daemon) |
|---|---|---|
| Claude Code, undeclared | 58, `info` | 73, `alert` (run 2) |
| paramiko client | 65, `info` | 75, `alert` (run 2), 80 on replay of run 1 |
| Claude Code, declared | 53, `declared_agent`, split across two tracks by early events | 60, `declared_agent`, label `claude-code` |
| Internet password guessing | empty tracks for `root` and `(unknown user)` | no tracks |

## Findings and fixes

1. **Real agents are slower and less regular than scripted ones.** Median gaps between commands were 3 to 8 seconds, with a coefficient of variation above 1. The `rhythm.regular` and `rhythm.subsecond` clues, calibrated on 0.4 to 0.9 s scripted gaps, never fired. Fix: a `rhythm.think_time` clue (+15) for 8 or more SSH exec channels with a median gap of 1.5 to 30 s and a coefficient of variation of at least 0.5. Scripts are regular or sub-second, and people use an interactive shell rather than a dozen separate exec channels. **It is tuned on three real sessions and is provisional** until pilots add human baseline data.
2. **Session plumbing was counted as activity.** On Ubuntu every SSH session runs about 20 processes before the client's command: PAM's MOTD scripts through `run-parts`, `lsb_release`, `uname`, the sshrc hook and `systemd --user`. The login shell sshd starts, `bash -c <command>`, also matched the tool-wrapper style clue for every human `ssh host cmd`. Fix: the correlator drops plumbing, recognised by a short list of anchored root commands plus process ancestry. It records the session shell as the command it wraps, so its `-c` no longer counts. On the undeclared session this cut recorded commands from 90 to 58.
3. **Failed logins became tracks through auditd.** `USER_LOGIN ... res=failed` records from password guessing each created a track, and could make an attacker's address the account's most recent track. Fix: failed and unknown-user audit logins are ignored.
4. **`whotyped check` misreported the OpenSSH version.** OpenSSH 8.2's `sshd` has no `-V`, and `check` reported the "unknown option" line as the version. Fix: report the line that carries the version.
5. **Older systemd warns about two unit keys.** systemd 245 ignores `ProtectProc` and `ProcSubset` with a harmless warning. Documented in the quickstart.

The three first-run sessions are in the labelled dataset, anonymised, as `testdata/dataset/real-claude-code-ssh`, `real-claude-code-declared` and `real-paramiko-mcp`. Every future scoring change is tested against them.

## What worked unchanged

- The documented install path, including `check --fix` and `sshd -t`, on an OpenSSH version outside the fixtures.
- The sshrc declaration hook: the declared agent's first command confirmed `AI_AGENT=claude-code` on the server, and every one-command session was labelled.
- ControlMaster-style correlation: the paramiko transport stayed one connection with all 14 channels.
- The PAM log line format without `(uid=N)`, and journald as the sshd source.
- `whotyped report` on the live alert file.

## Known issues left open

- On live traffic a single `style.tool_wrapper` hit (+8) still appears on some sessions, where replay of the same logs shows none. The likely cause is audit records for the sshrc runner and the session shell reaching the correlator out of order. It does not change any level on the pilot data.
- No human baseline. False-alarm rates need weeks of real traffic on several hosts.
- One host, one distribution, one OpenSSH version.

## Restoration

After the pilot the host was returned to its recorded prior state, and each item was verified: whotyped, its unit, config and state removed; the sshd drop-in and sshrc hook removed and sshd reloaded (`LogLevel INFO`, original `AcceptEnv`); the audit rules removed and auditd purged; the three test accounts deleted; temporary files removed; the host's services still active.
