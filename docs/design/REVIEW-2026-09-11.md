# Adversarial review of v0.1 (2026-09-11) and resolutions

Read-only security and correctness review of the first integrated build. Each finding was verified against code; H2 was also reproduced by running the binary. Resolutions landed in the "Harden v0.1" commit.

## High

| ID | Finding | Resolution |
|---|---|---|
| H1 | Any `AI_AGENT` env var, even from a background process attributed by user fallback, marked a track declared and suppressed all alert-level events. | Loud declared agents now emit `agent_detected`/`agent_high`; declaration accepted only via session-attributed processes or `ssh.env`; cleared when the declaring process ends; value validated and capped. |
| H2 | `Close session` (channel close) was treated as a connection close, splitting ControlMaster connections into fingerprint-less tracks (reproduced: 1 connection, 14 channels became 2 tracks, 5 connections). | Channel closes only touch the track. Fixture-driven pipeline test over the OpenSSH 9.6 log asserts one track, one connection, 14 execs, fingerprint kept. |
| H3 | Ansible profile matched a path fragment anywhere in command text with no source restriction, so an attacker could append `: /.ansible/tmp/ansible-tmp-x` to suppress rhythm, pty and style. | Structural, anchored Ansible matching with a required AnsiballZ clause; validator and `check` warn on profiles that suppress core families without users, CIDRs, fingerprints or a required clause; ratio denominator includes exec channels. |
| H4 | Webhook transport errors embedded the full Slack URL (the secret) in the daemon log. | `url.Error` unwrapped; only host and inner error logged; test asserts no token in error strings. |

## Medium

| ID | Finding | Resolution |
|---|---|---|
| M1 | Raw `AI_AGENT` values and process `comm` reached alerts, hints, Teams cards and terminal output uncleaned and uncapped. | Clean and cap at ingestion; Teams markdown and Slack fallback text escaped. |
| M2 | Freeze violations never fired for scores 40–69; configured freeze `level` ignored. | Violation on declared or level >= info; freeze level plumbed through. |
| M3 | `forced-command` sessions never counted as exec channels. | Treated like `command`. |
| M4 | Pre-auth failures created first-class tracks; brute force bloated state and poisoned user attribution. | No tracks on auth failure; bounded per-IP counter; empty users dropped. |
| M5 | Unbounded `argv0`/`exe` from audit records; quadratic replay. | Caps at 256/64 bytes; periodic flush; order tracking fixed. |
| M6 | `ssh -tt host cmd` cancelled `pty.none`. | PTY on exec channels tracked separately from shell PTYs. |
| M7 | GitHub Actions pinned by floating tags in a release job with id-token write. | Pinned to commit SHAs; Dependabot; `go mod tidy -diff` in CI. |

## Low

L1 atomic drop counter; L2 minimal env for journalctl; L3 O_NOFOLLOW and non-regular target refusal for root-written files, 0750 rules.d, per-run temp names in simulate; L4 dead config keys implemented or rejected; L5 memo release for absorbed tracks, syslog sink close, AF_NETLINK removed, zero-timestamp replay events rejected; L6 the tests listed above.

## What the reviewer found done well

Anchored regexes and JSON-only re-parsing (log-line injection defence); privacy defaults (only rule-listed env vars leave `/proc`, evidence is fragment plus count); single-goroutine correlator with ctx-aware sends and bounded queues; consistent handling of unset ids and PID reuse; escaped Slack markdown, STARTTLS-required email with TLS 1.2+; atomic state writes with strict permissions; a hardened systemd unit; `go mod verify`, `-trimpath`, SBOM, keyless signing and provenance in the release pipeline; pure fixture-tested parsers across OpenSSH 8.9 to 10.0.
